# Phase 6: the change in the ImpressCMS core

The notes of the earlier phases, and an earlier version of this one, assumed a core with renamed `Icms\...` classes (the
2.1 development line). That target was dropped: Protector 6 targets ImpressCMS 2.0.4, the `main` branch of
`impresscms/impresscms`, see [php-compatibility.md](php-compatibility.md). The planned loader change (registering
PSR-4 namespaces of modules) is not needed and was discarded; the module registers its own prefix.

What remains for the core is the **bundled copy**: ImpressCMS installs Protector during its web installation, from
`htdocs/install/modules/protector`, and starts it with `htdocs/plugins/preloads/protector.php`.

| Branch (core, from `main`) | Content |
|---|---|
| `protector-6x-bundle-2.0.x` | the 6.x module in `install/modules/protector`, and the preload that starts it from the module directory |

The branch is in `C:\Users\david\PhpstormProjects\worktrees\impresscms-204` (a worktree of the `impresscms_2.1` clone) and
is not pushed. The preload part is [core/0001-bundled-preload-2.0.x.patch](core/0001-bundled-preload-2.0.x.patch); the
bundle is regenerated by copying `root/` and `trust_path/` of this repository to
`htdocs/install/modules/protector/root` and `.../trust_path`.

* `plugins/preloads/protector.php` (still extends `icms_preload_Item`) includes `precheck.inc.php` and
  `postcheck.inc.php` from `modules/protector/include`, and falls back to the trust path, so a site that still runs
  Protector 5 keeps working until the module is updated. It parses on PHP 7.4.
* The installer (`page_tablescreate.php`, `page_modulesinstall.php`) needed no change: it copies `root/` and
  `trust_path/` of the bundle and installs the module.
* The forwarding files in `trust_path/modules/protector/include/` are no longer used by this preload; they stay in the
  bundle (identical to the module's distribution) because the module can also be installed into a core that has the
  old preload.

## Verification

A pristine 2.0.4 site was built with the branch's preload and bundle (`site.php core-pristine`), installed with the web
installer using only the module that the core ships (`PROTECTOR_BUNDLE_FROM_CORE=1`), and the 130 scenarios were run
against it on PHP 7.4 and PHP 8.4, including the update from Protector 5.2, which still keeps its code in the trust path.
The result is in the pull request.
